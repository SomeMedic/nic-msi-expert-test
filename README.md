# Цифровой эксперт

Локальный прототип для вопросов по нормативным PDF. Загрузите документы, дождитесь обработки и задайте вопрос в чате. Ответ содержит цитаты: каждую можно открыть вместе с нужной страницей оригинала. Если сведений недостаточно, система отказывает в ответе. Черновик проходит отдельную проверку перед показом пользователю.

Интерфейс состоит из одной страницы со светлой и тёмной темами. Загрузка, список документов, история и источники открываются в модальных окнах. Диагностика доступна через дополнительные действия.

## Как это работает

При загрузке PDF сохраняется в MinIO. Фоновый обработчик извлекает текст и таблицы, разбивает документ на фрагменты и строит индекс. Вопрос сначала проходит маршрутизацию, затем система объединяет полнотекстовый и векторный поиск и повторно ранжирует найденные фрагменты. Модель составляет ответ по этому контексту. Отдельный Critic проверяет утверждения и цитаты; при замечаниях допускается одна попытка исправления, затем — ответ или отказ.

| Компонент | Зачем нужен |
| --- | --- |
| React, TypeScript, nginx | Интерфейс и единая точка входа в приложение |
| FastAPI backend | Авторизация, документы, запросы пользователя и выдача источников |
| Agent runtime, LangGraph | Последовательность поиска, генерации, проверки и исправления ответа |
| Ingestion worker, Docling | Разбор PDF и таблиц; обработка документов отдельно от чата |
| Retrieval ML | FRIDA для векторного поиска и Qwen3 Reranker для уточнения результатов |
| PostgreSQL, pgvector | Документы, версии, задания, история и оба поисковых индекса в одной базе |
| Outbox publisher, Redis | Доставка фоновых заданий; их состояние сохраняется в PostgreSQL |
| MinIO | Оригиналы PDF и результаты разбора |
| vLLM, Qwen3-14B-AWQ | Локальное выполнение языковых ролей |
| OpenTelemetry, Jaeger | Поиск причин задержек и ошибок между сервисами |

Цитаты привязаны к конкретной версии документа. Архивные документы исключаются из актуального поиска. Модели работают локально; приложение не отправляет содержимое документов во внешние модельные API.

## Запуск

Нужны Python 3.12, uv 0.10.3 и Docker с поддержкой NVIDIA GPU. На Windows используется Docker Desktop с WSL2. Закреплённая языковая модель рассчитана на GPU; CPU-режим ниже относится только к ранжированию поиска. Для разработки интерфейса и проверок также нужны Node.js 22 и pnpm 10.20.0.

Команды выполняются из корня проекта. Первая подготовка требует интернета для зависимостей, образов и весов моделей, а также свободного места под них. Веса и пользовательские PDF в репозиторий не входят.

```sh
uv sync --frozen --all-packages
uv run --no-sync python scripts/bootstrap.py secrets
uv run --no-sync python scripts/prepare_models.py --allow-network
uv run --no-sync python scripts/prepare_parser_assets.py --allow-network
uv run --no-sync python scripts/prepare_runtime_identity.py --check
docker compose --profile models up -d --build --wait --wait-timeout 900
```

Подготовка проверяет размеры и контрольные суммы файлов по lock-файлам. Для повторной проверки без скачивания используйте `--verify-only` вместо `--allow-network`. При первом запуске Compose также создаёт служебные учётные записи и применяет миграции. Загрузка моделей и первая сборка могут занять значительное время.

Откройте [localhost:8080](http://localhost:8080). Для работы с документами введите ключ из локального файла `.secrets/local/operator_access_key`. Ключ администратора находится в `.secrets/local/admin_access_key`; он нужен для административных действий. Эти файлы создаются автоматически, существующие ключи сохраняются.

Загрузите PDF через кнопку добавления, заполните сведения о документе и дождитесь готовности индекса. После этого задавайте вопросы по его содержимому и открывайте цитаты. Правовой статус и редакцию документа указывает оператор; приложение не обновляет нормативные акты из интернета.

Для изменения порта и других параметров скопируйте `.env.example` в `.env`. По умолчанию интерфейс доступен только с локального компьютера. Команды для просмотра состояния и остановки:

```sh
docker compose --profile models ps -a
docker compose --profile models logs --tail 100
docker compose --profile models down
```

Остановка сохраняет данные в Docker volumes. Не добавляйте `--volumes`, если хотите сохранить загруженные документы и историю.

### Ранжирование на GPU

По умолчанию ранжирование работает на CPU. Чтобы включить CUDA, задайте `EXPERT_RERANKER_DEVICE=cuda` в `.env` и запустите:

```sh
docker compose -f compose.yaml -f infra/compose/reranker-gpu.yaml --profile models up -d --build --wait --wait-timeout 900
```

Для возврата задайте `EXPERT_RERANKER_DEVICE=cpu` и повторите команду. Индекс перестраивать не нужно. Ранжирование и языковая модель делят память GPU, поэтому выигрыш зависит от доступной памяти и нагрузки.

## Проверки

После установки Python-зависимостей выполните:

```sh
pnpm --dir apps/frontend install --frozen-lockfile
uv run --no-sync python scripts/prepare_test_assets.py --allow-network
uv run --no-sync python scripts/verify_project.py
```

Эта команда запускает Ruff, mypy, проверку OpenAPI, модульные и контрактные тесты, тесты интерфейса и сборку. Набор тестов охватывает основные сценарии: ответ с цитатами, отказ, проверка и исправление ответа, поиск, загрузка и права доступа. Для этих проверок нужны только небольшие файлы токенизатора, полные веса и GPU не требуются. Интеграционные тесты требуют отдельно запущенных PostgreSQL, Redis и MinIO.

Прототип предназначен для локальной демонстрации. Корректность трактовки документа нужно проверять по цитатам; полная оценка качества на большом наборе вопросов ещё не завершена. В проверках безопасности зависимостей и образов остаются незакрытые замечания. Скорость зависит от оборудования, объёма контекста и необходимости исправлять ответ.
